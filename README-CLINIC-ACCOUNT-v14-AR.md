# Smart Dental Clinic — مراجعة إعدادات حساب العيادة v14

## النسخة الأساسية
تم إنشاء هذا التحديث انطلاقًا من Clinic Profile v13. **لم تُضف صفحة جديدة**؛ التعديل داخل `/clinic/account-settings` الأصلي.

## التغييرات
- عرض بريد مدير العيادة وهاتفه الحقيقيين من `sdc."USER"` بدل قيم تجريبية.
- حفظ البريد والهاتف بعد التحقق من كلمة المرور الحالية، والتحقق من صيغة المدخلات وتكرار البريد.
- حفظ اللغة المفضلة في `sdc."USER"."Preferred_Language"` (`ar` أو `en`). **حفظ التفضيل لا يعني تفعيل ترجمة إنجليزية لجميع الصفحات**.
- تسجيل التعديلات في `AUDIT_LOG` ضمن معاملة PostgreSQL قابلة للتراجع عند الفشل.
- الإبقاء على واجهات تغيير كلمة المرور وMFA ورموز الاسترداد والجلسات الحالية بدون إنشاء صفحات مكررة.
- إزالة النماذج التجريبية غير المرتبطة من صفحة إعدادات حساب العيادة.

## تركيب الـPatch
1. أوقف السيرفر واحتفظ بنسخة احتياطية من مجلد المشروع.
2. فك ضغط `Smart-Dental-Clinic-Clinic-Account-Patch-v14.zip`.
3. انسخ **محتويات ZIP** فوق مجلد v13 الذي يحتوي `package.json` و `server.js`، ووافق على استبدال الملفات المتطابقة.
4. لا تستبدل `.env`. لا تحتاج إلى SQL جديد أو Seed. لا تحذف قاعدة البيانات.
5. من CMD داخل مجلد المشروع:

```cmd
npm test
npm start
```

عند استعمال نسخة المشروع الكامل في مجلد آخر، انقل `.env` إليه بأمان ثم شغّل `npm install` و`npm test` و`npm start`.

## اختبار عملي في PostgreSQL
- افتح `/clinic/account-settings` من حساب **مدير عيادة معتمدة**.
- تأكد من ظهور البريد والهاتف الحقيقيين.
- عدّل رقم الهاتف وأدخل كلمة المرور الحالية، ثم احفظ وحدّث الصفحة. يجب أن تبقى القيمة محفوظة.
- جرّب كلمة مرور خاطئة؛ يجب رفض الحفظ.
- غيّر تفضيل اللغة، ثم حدّث الصفحة؛ الاختيار يجب أن يبقى محفوظًا. صفحات النظام لا تزال عربية.
- اختبر فتح MFA والجلسات وتغيير كلمة المرور من نفس الصفحة.
- إذا غيّرت بريد تسجيل الدخول، استخدم البريد الجديد في تسجيل الدخول التالي.

## تنبيهات مهمة قبل الإطلاق الفعلي
- تغيير بريد الحساب في هذه النسخة **لا يرسل رسالة تحقق للبريد الجديد**؛ يلزم بناء إثبات ملكية البريد قبل الإطلاق العام.
- تم اختبار القوالب والمسارات و137 اختبارًا برمجيًا محليًا. لم يتم اختبار PostgreSQL الموجود على جهازك أو التصفح الفعلي.
- الأسرار المرسلة سابقًا يجب تدويرها وفق خطة تراعي إعادة تشفير أسرار MFA؛ لا تغيّر `MFA_ENCRYPTION_KEY` عشوائيًا.
