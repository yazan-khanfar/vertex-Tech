# Smart Dental Clinic — Patients CSRF Fix v18.1

## المشكلة
عند الضغط على «إضافة المريض» تظهر «انتهت صلاحية نموذج الحفظ» فورًا، لأن النموذج كان يرسل اسم الحقل `_csrf` بينما مسار الحفظ في `src/clinic-patients/router.js` يستخدم `validateSessionCsrf()` الذي يتحقق من `csrf_token`.

## الإصلاح
- استبدال اسم الحقل المخفي بـ `csrf_token` في `views/clinic/patients.ejs` فقط.
- إضافة اختبار يمنع تكرار عدم التطابق ويؤكد عمل `validateSessionCsrf()` مع الحقل الصحيح.
- لم يتم تعديل منطق الحماية أو تصميم الصفحة أو أي CSS أو SQL.

## التركيب (Patch فوق v18)
1. أوقف السيرفر.
2. خذ نسخة احتياطية للملفين المذكورين.
3. فك ضغط الـPatch وانسخ مجلدي `views` و`tests` إلى مجلد مشروع v18 الذي يحتوي `package.json` ووافق على استبدال الملفين.
4. شغّل `npm test` ثم `npm start`.
5. افتح `/clinic/patients`، وحدّث الصفحة، ثم افتح إضافة مريض وجرّب الحفظ.

## الاختبار المتوقع
ينتقل النظام إلى `/clinic/patient-details?patient=...` عند حفظ بيانات صحيحة، ثم يظهر المريض في قائمة المرضى. في حال ظهور خطأ مختلف، افحص نافذة CMD؛ لا تشارك أي بيانات شخصية للمريض.

لا حاجة إلى `npm install` إن كانت المكتبات موجودة؛ لا تحتاج تحديث قاعدة البيانات أو `.env`.

> الاختبارات الآلية لا تثبت نجاح الحفظ على PostgreSQL المحلية؛ يجب اختباره على جهاز المستخدم.
