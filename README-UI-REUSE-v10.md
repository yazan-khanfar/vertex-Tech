# تصحيح الصفحات المكررة — v10

هذا الإصدار مبني على **Doctor Schedule Edit Merged v9** (بما فيه تحديث 24 ساعة v8 والتشغيل اليومي v7)، ويعيد استخدام الصفحات الأصلية بدل الواجهات المضافة أو المختصرة.

## الأفضل: استخدام النسخة الكاملة
1. أوقف `npm start` في المشروع القديم.
2. احتفظ بنسخة احتياطية من المشروع، ولا تحذف قاعدة البيانات.
3. فك ملف **Original Pages Reuse Merged v10** في مجلد جديد.
4. انسخ `.env` القديم الخاص بك إلى المجلد الذي يحتوي `package.json` (الملف غير موجود في ZIP لأسباب أمنية).
5. افتح CMD داخل المجلد الجديد وشغّل:
   ```cmd
   npm install
   npm test
   npm start
   ```
6. لا تشغّل SQL جديدًا ولا Seed.

## إذا استخدمت Patch بدل النسخة الكاملة
1. أغلق السيرفر وخذ نسخة احتياطية.
2. انسخ الملفات الموجودة داخل الـPatch فوق مجلد المشروع الأصلي مع الإبقاء على المسارات.
3. احذف **هذه الملفات القديمة الثلاثة فقط** من مشروعك (إذا كانت موجودة):
   ```cmd
   del views\account\doctor-profile.ejs
   del views\auth\security.ejs
   del src\account\doctor-profile-router.js
   ```
4. نفّذ `npm test` ثم `npm start`.

## روابط الاختبار
- طبيب معتمد **بدون عيادة**: `/doctor/profile`؛ يعرض حسابه ويحافظ على إعداد MFA وكلمة المرور والجلسات.
- MFA: داخل `/doctor/profile#sdc-mfa`، `/patient/profile#sdc-mfa`، `/admin/settings#sdc-mfa`، `/staff/profile#sdc-mfa` أو `/clinic/account-settings#sdc-mfa` حسب الدور.
- زيارة فعلية: من `/doctor/appointments` → «فتح الزيارة»؛ تعرض صفحة `/doctor/visit?booking_id=...` **الأصلية** بأقسامها، مع حفظ الشكوى والفحص.
- المشرف: `/admin/approvals` ثم «عرض» لعيادة معتمدة → `/admin/clinic-details?id=...`. أما طلب الاعتماد الجديد فيبقى ضمن `/admin/clinic-application-details?id=...` لأنه سيناريو مختلف.

## الأمان وحدود الفحص
نجحت اختبارات القوالب والروابط والفحوص البرمجية المحلية. **لم يتم اختبار هذه النسخة على PostgreSQL عندك أو عبر المتصفح الحقيقي.** لا تغيّر مفاتيح MFA تلقائيًا أثناء تحديث الملفات؛ لقد ظهرت أسرار بيئة تطوير سابقة في المحادثة وتحتاج خطة تدوير آمنة بعد التأكد من عمل الحسابات.

اقرأ `UI-REUSE-AUDIT-AR.md` للقائمة التفصيلية وما بقي غير مرتبط.
