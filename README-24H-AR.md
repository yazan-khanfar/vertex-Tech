# تحديث v8 — دعم دوام العيادة 24 ساعة

## النسخة الأساس
يُركَّب فوق **Smart-Dental-Clinic-Daily-Operations-Merged-v7** أو نسخة أحدث تحمل نفس الملفات دون تعديلات متعارضة. لا يحتوي التحديث على مشروع كامل، بل على الملفات المعدلة فقط.

## التغييرات
- `views/clinic/profile.ejs`: زر "دوام 24 ساعة" لكل يوم وزر "دوام 24 ساعة طوال الأسبوع" في صفحة إعدادات العيادة نفسها، مع عرض صحيح للجدول بعد إعادة فتح الصفحة.
- `public/clinic/assets/app.js`: إرسال `00:00`–`24:00` في JSON للدوام الكامل، ومنع إضافة فترة ثانية متداخلة في اليوم الكامل، مع المحافظة على سلوك الفترات اليدوية السابق.
- `src/clinic-settings-service.js`: قبول فترة اليوم الكامل، ورفض `00:00`–`00:00` أو أي دوام عابر لمنتصف الليل غير مُمثل كدوام كامل، مع حفظه في جدول `CLINIC_WORKING_HOURS` الموجود.
- `src/appointments/service.js`: التعامل مع نهاية اليوم `24:00` بصورة صريحة في توافر الحجز.
- `src/patient-directory-service.js`: عرض أوقات العيادة في دليل المريض بصورة متوافقة مع `24:00`.
- `tests/clinic-settings.test.js`: حالات اختبار جديدة لليوم الكامل ومنع التداخل والحفظ والتوافر والواجهة.

## التركيب — Windows
1. احتفظ بنسخة احتياطية من مشروعك الحالي ثم أوقف السيرفر (`Ctrl+C`).
2. فك ضغط الحزمة في مجلد مؤقت.
3. انسخ **المجلدات `src` و`views` و`public` و`tests` من داخل ZIP** إلى جذر مشروعك الحالي (حيث `package.json` و`server.js`)؛ وافق على استبدال الملفات المتطابقة.
4. لا تغيّر `.env`، ولا تشغّل SQL أو Seed ولا تحذف قاعدة البيانات. لا تحتاج `npm install` إذا كانت المكتبات موجودة.
5. داخل المشروع شغّل:
   ```cmd
   npm test
   npm start
   ```
6. افتح `/clinic/profile` ← أوقات العمل. اختر "دوام 24 ساعة" بجانب اليوم المطلوب، أو "دوام 24 ساعة طوال الأسبوع"، ثم **حفظ ساعات العمل**. حدّث الصفحة للتحقق من بقاء الإعدادات.

## ملاحظات مهمة
- PostgreSQL يتيح `TIME '24:00'` ويخزّنه على أنه **نهاية اليوم نفسه**. لا تغيّر قيود قاعدة البيانات الأصلية.
- **إتاحة الحجز تتطلب كذلك دوام الطبيب**؛ مجرد كون العيادة مفتوحة 24 ساعة لا يعني وجود طبيب في كل ساعة.
- نظام الحجز الحالي يعالج المواعيد ضمن تاريخ يوم واحد. موعد يتجاوز منتصف الليل (مثل 23:30 إلى 00:30 من اليوم التالي) ليس ضمن نطاق هذا التصحيح؛ نحتاج معالجة مستقلة لتلك الحالة حتى لا نتجاوز قيود التاريخ/المدة.
- هذا الإصلاح لا يغيّر تصميم الصفحة أو أوقات الاستثناءات، ولا يضيف صفحات أو جداول.
- تم فحص JavaScript واختبارات الوحدات وقوالب الـ110؛ لم يُختبر الحفظ على PostgreSQL المحلي لديك، لذا يتطلب تأكيدًا بعد التركيب.
