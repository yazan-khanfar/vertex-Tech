# Smart Dental Clinic — Clinic Dashboard v12

**الأساس:** آخر نسخة كاملة v11 (`Smart-Dental-Clinic-Original-Pages-MFA-Fixed-Merged-v11.zip`).

## ما تغيّر

ربط `/clinic/index` بالبيانات الفعلية داخل **نفس قالب EJS الأصلي**، دون إضافة صفحة جديدة أو تغيير CSS/JS للواجهة:

- اسم العيادة وتاريخ اليوم بتوقيت `Asia/Hebron`.
- حالة فتح العيادة الآن، بما يشمل دوام الأسبوع والإغلاق الاستثنائي والساعات الاستثنائية.
- إحصائيات المواعيد اليوم حسب الحالة، وطلبات الحجز التي تنتظر موافقة العيادة.
- مواعيد اليوم بروابط تفاصيل الحجز الحقيقية.
- الأطباء المدرجون على جدول اليوم ممن لم يسجل لهم غياب، مع شرط تقاطع الدوام مع ساعات العيادة.
- عدد الفواتير الصادرة ذات الرصيد غير المسدد، حسب `sdc.invoice_balances`.
- تنبيهات حقيقية لطلبات الحجز وتغيير الموعد والفواتير الصادرة غير المسددة.
- حالات فارغة واضحة، بلا بيانات مريض أو طبيب تجريبية.
- الاستعلامات تقيد جميع البيانات بـ`Clinic_ID` الفعلي من جلسة مدير العيادة.

**لم نغيّر** أي جدول أو قيد SQL، أو صفحة جديدة، أو تصميم CSS، أو JavaScript الخاص بالواجهة.

## خطوات تركيب Patch

1. انسخ مجلد المشروع الحالي واحتفظ بنسخة احتياطية. أوقف السيرفر بـ `Ctrl+C`.
2. افتح ZIP الخاص بالـPatch، ثم انسخ **محتوياته** مباشرة فوق مجلد مشروع v11 الذي يحتوي `server.js` و`package.json`، ووافق على استبدال الملفات الموجودة.
3. لا تستبدل `.env` أو `MFA_ENCRYPTION_KEY`، ولا تشغل SQL أو Seed.
4. افتح CMD في جذر المشروع ثم نفّذ:

```cmd
npm test
npm start
```

إذا ظهر `Cannot find module` شغّل `npm install` مرة واحدة، ثم أعد المحاولة.

## استخدام النسخة الكاملة

إذا أردت تجنب الدمج اليدوي، فك النسخة الكاملة v12 بمجلد منفصل؛ ملف `package.json` موجود في جذر محتويات ZIP. انسخ `.env` القديم إليها فقط، ثم نفّذ `npm install` و`npm test` و`npm start`. أبقِ قاعدة PostgreSQL كما هي.

## اختبار قبول صفحة لوحة العيادة

1. ادخل بحساب مدير العيادة وافتح `http://localhost:3000/clinic/index`.
2. تحقق أن اسم عيادتك الحقيقي يظهر، وأن الأرقام تتطابق مع `/clinic/appointments` لنفس التاريخ.
3. افتح موعدًا من «مواعيد اليوم» وتأكد أنه يأخذك لنفس صفحة التفاصيل الأصلية.
4. أضف موعدًا بانتظار الموافقة من حساب المريض؛ يجب أن يزيد المؤشر وتظهر مهمة مراجعته.
5. جرّب يوم إغلاق استثنائي: يجب أن يظهر «مغلقة الآن» (إذا كان اليوم هو يوم الإغلاق)، دون عرض طبيب كمتاح اليوم.
6. اختبر عدم وجود أي مواعيد أو أطباء؛ يجب أن ترى رسائل فارغة واضحة بدل أسماء وهمية.
7. إذا تدير أكثر من عيادة، بدّل العيادة النشطة وتأكد أن الأرقام تتغير ولا تختلط بيانات العيادات.

## ملاحظات وحدود التحقق

- جرى الفحص **بالاختبارات الآلية ومخزن بيانات مزيف للاختبارات فقط**، وليس باتصال بقاعدة بياناتك المحلية أو بمتصفحك؛ لذلك لا تعتبر الصفحة معتمدة نهائيًا قبل اختبارها على جهازك.
- سطر «الأطباء المتاحون اليوم» يعني الأطباء **المجدولين اليوم**، وليس ضمان وجود موعد شاغر لحجز جديد. توفر الحجز الفعلي يبقى من خدمة المواعيد الحالية.
- قد تشير الاختصارات في لوحة التحكم إلى صفحات موجودة لكنها ما زالت تجريبية (مثل الموظفين والفواتير والمتابعات)؛ لا تمثّل هذه المرحلة ربط تلك الصفحات.
- «الفواتير غير المكتملة» هنا هي الفواتير **الصادرة** فقط ذات `remaining_amount > 0` في العرض `sdc.invoice_balances`.

## الخطوة التالية وفق مراجعة دور العيادة

بعد اجتياز اختبار الصفحة على PostgreSQL، نراجع `/clinic/profile` بجميع تبويباتها، ثم `/clinic/account-settings` ثم بقية الصفحات حسب تقرير مراجعة v11. لا يتم تعديل صفحة أخرى دون حاجة.
