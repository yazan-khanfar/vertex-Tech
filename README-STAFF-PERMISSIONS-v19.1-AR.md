# Smart Dental Clinic — إصلاح صلاحيات الموظفين v19.1

## أساس التحديث

يُركب هذا التحديث فوق **Clinic Batch 1 v19** فقط. الإصلاح يستخدم نفس صفحات EJS الأصلية؛ لا توجد صفحة جديدة أو SQL جديد أو تعديل CSS.

## التعديلات

- يعرض الهيدر وقائمة الجوال الأقسام المخوّلة فقط **من السيرفر**، وليس بعد ظهورها في المتصفح.
- تظهر بطاقات ومهام لوحة الموظف تبعًا لصلاحياته الفعلية. اختفت الإحصاءات التجريبية الثابتة من اللوحة واستُبدلت بشرطة حتى يُربط مصدرها الحقيقي لاحقًا.
- يستخدم اسم الموظف واسم العيادة وصلاحيات العضوية الحالية من الجلسة وقاعدة البيانات بدل بيانات C-008/نور التجريبية في سياق العيادة.
- يرفض Backend الطلبات غير المصرح بها أو غير المدرجة في قائمة المسارات الآمنة، سواء بالروابط المباشرة أو طلبات POST.
- تتحقق صلاحيات `STAFF_AT` و`STAFF_PERMISSIONS` من العيادة النشطة وحالة العضوية active قبل العرض.
- يحتفظ بميزة إبطال الجلسات عند تغيير الصلاحيات التي كانت موجودة في v19.

## التركيب

1. أوقف السيرفر وخذ نسخة احتياطية من المشروع.
2. فك ضغط Patch فوق جذر مشروع v19 نفسه (المجلد الذي فيه `server.js` و`package.json`). وافق على استبدال الملفات المطابقة.
3. **لا تغيّر** `.env` أو قاعدة البيانات أو أي ملف SQL. لا تُشغّل Seed.
4. نفّذ `npm test` و`npm start`. لو ظهرت مشكلة مكتبات في تثبيت جديد نفّذ `npm install` أولًا.
5. سجّل دخول موظف يملك `appointments.view` فقط، وحدّث الصفحة بـ Ctrl+F5.

## اختبارات قبول الدفعة

- تظهر `الرئيسية` و`المواعيد` و`الملف الشخصي` في القائمة العلوية وقائمة الجوال، دون المرضى أو الفواتير أو المختبرات.
- `/staff/appointments` يعمل للموظف ويعرض مواعيد عيادته.
- `/staff/patients` و`/staff/invoices` و`/staff/lab-cases` تُرجع **403** لهذا الموظف ولو كتب رابطها مباشرة؛ ولا تُرسل بيانات هذه الصفحات له.
- بعد منح `patients.view_admin` وتسجيل الدخول من جديد تظهر صفحة المرضى، وبعد إزالة الصلاحية وتسجيل الدخول من جديد تُمنع؛ يجب ألا تعيد الجلسات السابقة منح صلاحيات قديمة.
- كرّر في الجوال وتحقق أن تصميم البطاقات والألوان لم يتغير.

## نتائج الفحص وما بقي

- نجح 12 اختبارًا متخصصًا في الموظفين والسياسات، ونجح فحص البنية الموحدة لـ90 صفحة ذات الهيدر والفوتر.
- تعذّر تشغيل `npm test` الكامل داخل بيئة تجهيز النسخة بسبب عدم توفر تبعيات npm واتصال السجل؛ يجب تشغيله على جهازك.
- لم تُجرَ تجربة PostgreSQL المحلية أو اختبار متصفح فعلي هنا؛ اعتمد التحديث بعد تجربة الحساب الحقيقي.
- **بعض صفحات الموظف المرخصة ما زالت تحتوي بيانات عرض تجريبية**، وهذا التحديث لا يربطها بعد؛ لا تعاملها على أنها بيانات مرضى أو فواتير فعلية.
- يُنصح باستكمال ربط البيانات في دور الموظف بعد الانتهاء من صفحات العيادة المشتركة.
