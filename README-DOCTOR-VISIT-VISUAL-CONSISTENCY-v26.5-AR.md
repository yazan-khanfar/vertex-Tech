# Smart Dental Clinic — v26.5 | توحيد عرض صفحة الزيارة بين المرضى

## السبب المحدد من الكود

- بعد اكتمال الزيارة، يحوّل `public/doctor/assets/visit-bridge.js` حقل سبب الزيارة وحقل ملاحظات الفحص إلى `readonly`.
- تنسيق `.form-control[readonly]` العام في `public/doctor/assets/styles.css` يغيّر خلفيته إلى درجة زرقاء فاتحة. لذلك يختلف شكل الحقول بين زيارة مكتملة وزيارة لم تكتمل.
- زر «حفظ نتائج الفحص» يستخدم `btn-outline-primary`: قاعدة `:hover` العامة تحوّله إلى أزرق ممتلئ عند وجود مؤشر الفأرة عليه. هذا ليس اختلاف صفحة بين مريضين.
- تحديد مربعات نتائج الفحص وألوان الأسنان يعتمد على البيانات الطبية المسجلة لكل زيارة، وينبغي أن يستمر بالاختلاف بين المرضى، وليس خطأ تنسيق.

## التعديلات (محصورة داخل صفحة زيارة الطبيب)

1. تعديل CSS للحقلين `#chiefComplaint` و`#examinationNotes` عند `readonly`: خلفية بيضاء وخط مطابق لحالة التحرير، مع استمرار خاصية منع الكتابة.
2. إبقاء زر «حفظ نتائج الفحص» بإطار أزرق عند تمرير المؤشر، مع تغير حدود الإطار بشكل طفيف للإشارة للتفاعل، ومن دون التحوّل إلى زر ممتلئ.
3. إضافة `aria-readonly` ونص توضيحي إلى الحقلين عند اكتمال الزيارة، للمساعدة في فهم منع التعديل.
4. تعطيل مربعات نتائج الفحص بعد اعتماد التقرير (أو قبل بدء الزيارة)، لأن الحفظ في تلك الحالة ممنوع أصلًا. تبقى قابلة للتعديل بعد اكتمال الزيارة ما دام التقرير غير معتمد، بما يوافق منطق الحفظ الحالي.
5. لم تُغيّر بيانات المريض أو حالات الأسنان أو ربط PostgreSQL أو أي صفحة أخرى.

## الملفات

- `public/doctor/assets/styles.css` — إضافة قواعد CSS مقيّدة بصفحة الزيارة فقط.
- `public/doctor/assets/visit-bridge.js` — تحسين وصول الحقول وحالة خيارات الفحص.
- `tests/doctor-visit-visual-consistency-v26-5.test.js` — اختبارات انحدار للسبب والتصحيح.

## نتائج الفحوص

- نجحت 24 حالة اختبار تخص صفحة الزيارة والدفعات السابقة المرتبطة بها.
- نجح تصيير ثلاث حالات EJS تجريبية: زيارة قيد العلاج، زيارة مكتملة بتقرير معتمد، وزيارة لم تبدأ.
- تعذّرت لقطة المتصفح الآلية في بيئة الفحص (Chromium انتهى بانتهاء المهلة)، لذا المطابقة البصرية على متصفح المستخدم **غير مؤكدة بعد**.
- لم يجر اختبار جديد على قاعدة PostgreSQL الحقيقية؛ التعديل محصور بالتنسيق وتفاعلات العرض.

## طريقة التطبيق

- النسخة **Patch** تُنسخ فوق مشروع **v26.4** فقط مع استبدال الملفات بنفس المسارات.
- احتفظ بـ `.env` والملفات الطبية المحفوظة، وأعد تشغيل الخادم.
- نفذ `Ctrl + F5` في صفحة الطبيب؛ لأن ملف CSS وJavaScript قد يكونان محفوظين في Cache.
- افتح زيارة لا تزال قيد العلاج، وأخرى مكتملة، وقارن خلفية حقلي السبب والفحص وشكل زر الحفظ. يجب أن يتطابق تنسيق الحقول ويظل منع الكتابة في الزيارة المكتملة فعالًا.
- مربعات الفحص المحفوظة وألوان الأسنان يجب أن تعكس بيانات كل زيارة الخاصة؛ اختلافها طبيعي وصحيح.
