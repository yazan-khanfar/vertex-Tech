# المرحلة الثالثة — اعتماد ورفض ترخيص الطبيب من Super Admin

## ما الذي تغير؟
- شاشة انتظار الترخيص `views/onboarding/doctor/verification-pending.ejs`: حُذف رابط «متابعة العرض بعد التحقق» و«عرض مثال: يحتاج استكمال»، وكذلك نافذة دعم تجريبية غير متصلة بخدمة حقيقية. بقيت رسالة الحالة ورابط الرجوع لتسجيل الدخول.
- `GET /admin/doctors`: يعرض أطباء حقيقيين من `sdc."DOCTOR"` و`sdc."USER"` و`sdc."HAS_SPECIALTY"` بدل الطبيب التجريبي `D-108`. زر «مراجعة الترخيص» يحمل رقم الطبيب الحقيقي، وأزلنا إجراءات الطبيب غير المربوطة في جدول الأطباء.
- `GET/POST /admin/doctor-license-review?id=...`: حقول الطبيب للقراءة فقط من قاعدة البيانات، وثلاثة مربعات تحقق تؤكد شروط الاعتماد وسبب كتابي للقرار. زر الاعتماد والرفض يرسلان POST فعليًا، ولا يستدعيان نافذة demo.
- `POST /admin/doctor-license-review`: يحفظ القرار في Transaction ويقفل الصف لمنع الموافقة المكررة. اعتماد: `License_Status=verified`, `Account_Status=active`, `Login_Enabled=true`. رفض: `License_Status=rejected`, `Account_Status=disabled`, `Login_Enabled=false`. حالة `rejected` **غير مسموح بها في USER.Account_Status** حسب ملف SQL؛ لذلك يُستخدم `disabled` للحساب بينما يكون ترخيص الطبيب `rejected`.
- يحفظ `License_Reviewed_By_User_ID` و`License_Review_Notes` وينشئ `AUDIT_LOG` مع `sdc.user_id` عبر `set_config` داخل نفس المعاملة. يطابق بذلك قيود قاعدة البيانات الفعلية.
- دخول مستقل للمشرف `GET/POST /admin/sign-in` باستخدام حساب `Super Admin` حقيقي وكلمة مرور scrypt؛ مبدئيًا **جلسة خادم واحدة في الذاكرة، للتطوير المحلي فقط** مع Cookie HttpOnly وSameSite وCSRF. جميع عناوين `/admin/*` تتطلب المشرف، بما فيها صفحات العرض التي لم نربط بياناتها بعد. تسجيل الخروج فعلي.

## 1. احتفظ بقاعدة البيانات وحساب الطبيب والمريض
لا تستورد ملف SQL مجددًا ولا تستخدم `DROP` أو `TRUNCATE`. انسخ ملف `.env` من النسخة السابقة إلى هذه النسخة الجديدة، ثم افتح PowerShell داخل المجلد:

```powershell
npm install
npm test
```

## 2. جهّز حساب Super Admin مرة واحدة فقط

نفّذ:

```powershell
npm run db:seed:admin
```

إذا كنت تستخدم Terminal تفاعليًا، سيطلب منك بريدًا إلكترونيًا جديدًا ورقم هاتف وكلمة مرور قوية **لا تقل عن 14 حرفًا** (إدخال كلمة المرور مخفي). الحساب يُنشأ كـ `Super Admin` بنطاق `System`، حالة `active` والدخول مفعّل. لا يغيّر أي حساب موجود ولا يُنشئ كلمة مرور افتراضية. إذا كان حساب Super Admin موجودًا مسبقًا، يتوقف بدل تكراره. لا تشارك كلمة المرور أو ملف `.env`.

للبيئات غير التفاعلية يمكن استخدام متغيرات `SDC_ADMIN_EMAIL`, `SDC_ADMIN_PHONE`, `SDC_ADMIN_PASSWORD` المؤقتة في Terminal فقط، وليس في ملف المشروع. احذف المتغيرات المؤقتة بعد الاستخدام.

## 3. شغّل وافتح لوحة الإدارة

```powershell
npm start
```

1. افتح `http://localhost:3000/admin/sign-in` وسجّل ببريد وكلمة مرور Super Admin.
2. افتح `http://localhost:3000/admin/doctors` وتأكد أن الطبيب ذو الترخيص الذي سجلته سابقًا يظهر بحالة «بانتظار المراجعة».
3. اضغط «مراجعة الترخيص»، وراجع الاسم والبريد والرقم والتخصصات.
4. إذا كانت البيانات صحيحة، علّم مربعات التحقق الثلاثة واكتب سببًا لا يقل عن 8 أحرف، ثم اضغط «اعتماد الرقم وتفعيل الحساب».
5. يجب أن تظهر رسالة نجاح وتصبح حالة الترخيص «معتمد» وحالة الحساب «فعال». لا يستطيع المشرف اعتماد القرار نفسه مرتين.
6. **لاختبار الرفض، سجّل طبيبًا آخر** ببريد ورقم ترخيص جديدين ثم اختر الرفض مع سبب. لا ترفض الطبيب الذي اعتمدته إلا إذا كان هذا قصدك في الاختبار.

## 4. تحقق من PostgreSQL

```sql
SELECT d."Doctor_ID",d."License_Number",d."License_Status",
       d."License_Reviewed_By_User_ID",d."License_Review_Notes",
       u."Account_Status",u."Login_Enabled"
FROM sdc."DOCTOR" d JOIN sdc."USER" u ON u."User_ID"=d."User_ID"
ORDER BY d."Doctor_ID" DESC;

SELECT "Occurred_At","Action_Type","Target_Reference","Reason","User_ID"
FROM sdc."AUDIT_LOG"
WHERE "Action_Type" IN ('doctor.license.approved','doctor.license.rejected')
ORDER BY "Log_ID" DESC;
```

## 5. حدود هذا الإصدار
- هذا الـBackend موصول بقسم تسجيل المريض والطبيب واعتماد ترخيص الطبيب فقط. **تسجيل دخول الأطباء والمرضى وMFA وإنشاء العيادة والمسارات الأخرى لم يُنفّذ بعد**؛ تفعيل `Login_Enabled` لا يعني إمكانية الدخول من الواجهة العامة قبل ربطها.
- جلسة المشرف في الذاكرة تضيع مع إعادة تشغيل Node.js. التطبيق يمنع الوصول إلى إدارة المشرف في `NODE_ENV=production` حتى بناء جلسات دائمة وMFA ومراقبة وحماية إنتاجية. لا تستخدم هذه النسخة للخدمة العامة.
- بقيت صفحات العرض في الأقسام غير المربوطة تحتوي على بيانات اختبار؛ لا تعرضها كبيانات حقيقية. تم تنظيف العناصر التجريبية فقط في مسار مراجعة الترخيص وشاشة الانتظار التي طلبتها.
- الاختبارات المنفذة محليًا هي اختبارات منطقية وقوالب ومسارات باستخدام بدائل لـ PostgreSQL. **اختبار قاعدة البيانات والـHTTP بالمتصفح يجب تنفيذه على جهازك**، وفق خطوات هذا الملف.
- ملف SQL الأصلي (57 جدولًا) محفوظ دون تغيير، وكذلك بقية واجهات الأدوار.
