# Smart Dental Clinic — التحقق بخطوتين MFA (تطوير محلي)

هذه النسخة مبنية على Unified Login v1 ولا تتطلب حذف قاعدة البيانات أو أي حساب. استخدمت الجداول الموجودة في سكيما PostgreSQL: `sdc."USER"` و`"USER_RECOVERY_CODES"` و`"AUDIT_LOG"`، دون إنشاء جداول جديدة أو تعديل السكيما.

## قبل التشغيل (إلزامي لتفعيل MFA)

انسخ `.env` الخاص بك من المشروع السابق إلى جذر هذه النسخة ولا تشاركه. احتفظ بالمتغير `DATABASE_URL` كما هو. لإنشاء مفتاح خاص بتشفير أسرار تطبيق المصادقة، نفّذ الأمر التالي داخل CMD أو PowerShell:

```cmd
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

انسخ القيمة المكوّنة من 64 خانة hexadecimal إلى ملف `.env`، في سطر مستقل بالشكل التالي (استخدم قيمتك الخاصة، لا النص الموجود هنا):

```dotenv
MFA_ENCRYPTION_KEY=PUT_YOUR_64_CHARACTER_RANDOM_HEX_HERE
```

**احتفظ بنسخة محمية من المفتاح خارج المجلد**: فقدانه أو تغييره بعد تفعيل MFA سيمنع فك تشفير الأسرار القديمة، ولن تنفع رموز تطبيق المصادقة. لا تضعه في Git أو المحادثة. لا تستخدم مفتاحًا من أمثلة الإنترنت.

بعدها نفّذ:

```cmd
npm install
npm test
npm start
```

## خطوات التفعيل الفعلية

1. ادخل من `/auth/login` بحساب مريض أو طبيب أو مشرف موجود.
2. افتح صفحة إعدادات الحساب لدورك، واضغط **إدارة التحقق بخطوتين**، أو افتح `/auth/security` مباشرة.
3. أدخل **كلمة المرور الحالية** لتوليد سر جديد (السر يبقى مؤقتًا في الجلسة إلى حين إثبات ملكيته).
4. افتح تطبيق مصادقة على هاتفك، وأضف المفتاح المعروض يدويًا. الحساب من نوع TOTP بـ6 أرقام ومدة 30 ثانية. لا يعتمد على خدمة خارجية.
5. اكتب رمز التطبيق واضغط **تأكيد التفعيل**.
6. انسخ **الرموز الثمانية** التي تظهر مرة واحدة فقط، واحفظها في مكان آمن منفصل عن الهاتف. لا تشارك الرموز أو المفتاح مع أحد.
7. سجّل خروجًا، ثم ادخل ببريدك وكلمة مرورك. ستذهب إلى `/auth/mfa`، ولا يتم إصدار جلسة كاملة حتى تدخل رمزًا صحيحًا.
8. اختبر رمز استرداد واحدًا. يجب أن يعمل مرة واحدة فقط ثم يُرفض عند استخدامه ثانية.
9. للتعطيل من `/auth/security`: أدخل كلمة المرور الحالية بالإضافة لرمز من التطبيق أو رمز استرداد غير مستخدم.

### فحص PostgreSQL (لا يعرض أسرارًا)

```sql
SELECT "User_ID", "Two_Factor_Enabled",
       ("Two_Factor_Secret_Encrypted" IS NOT NULL) AS secret_is_stored
FROM sdc."USER"
ORDER BY "User_ID";

SELECT "User_ID", COUNT(*) FILTER (WHERE "Used_At" IS NULL) AS unused_codes
FROM sdc."USER_RECOVERY_CODES"
GROUP BY "User_ID";

SELECT "Occurred_At", "Action_Type", "Target_Type", "Target_Reference", "User_ID"
FROM sdc."AUDIT_LOG"
WHERE "Action_Type" LIKE 'account.mfa.%'
ORDER BY "Log_ID" DESC;
```

لا تستعلم عن محتوى `Two_Factor_Secret_Encrypted` أو `Code_Hash` ولا تشارك لقطات تتضمنها.

## حدود هذه المرحلة

- هذا ربط MFA فعلي مع PostgreSQL في **خادم تطوير محلي واحد فقط**؛ لم يتم اختباره بعد على جهازك.
- تحقق TOTP يتم دون الاعتماد على طرف ثالث، والمفتاح مُشفّر AES-256-GCM، ورموز الاسترداد مخزّنة كـSHA-256 لرُموز عشوائية 128-bit وقابلة للاستهلاك مرة واحدة.
- يتم تحديد جلسة تحدي MFA لمدة خمس دقائق وبحد خمس محاولات. جلسات الدخول والحماية من إعادة استخدام رمز TOTP مؤقتة **في ذاكرة Node.js**؛ لذلك لا يدعم التشغيل الإنتاجي أو التشغيل على أكثر من خادم دون تخزين مشترك دائم، وتوزيع ذي ضمانات ذرية، وضبط المعدلات.
- لم ننفّذ بعد سياسة MFA العامة الإلزامية من لوحة Super Admin، ولا تغيير/استعادة كلمة المرور عبر البريد، ولا إدارة الأجهزة الدائمة. لا تعتبر هذه النسخة جاهزة للنشر على الإنترنت.
- حذف `MFA_ENCRYPTION_KEY` أو تغييره ليس طريقة لتعطيل MFA. سيمنع الدخول إلى الحسابات المفعّل لها MFA.
- الرمز يظهر كنص يدوي لا كصورة QR، لأن استدعاء خدمات QR خارجية قد يسرب سر المصادقة. يمكن إضافة QR محلي لاحقًا دون تغيير آلية الحماية.
- هناك بيانات نموذجية غير متصلة بقاعدة البيانات في لوحات العمل الأخرى؛ لم تُعدّل في هذا الإصدار.
