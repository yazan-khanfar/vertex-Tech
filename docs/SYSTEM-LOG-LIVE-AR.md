# سجل النظام — ربط العرض الحقيقي

تم ربط صفحة `/admin/system-log` بالجدول `sdc."AUDIT_LOG"` بدل السجل الوهمي. يحتاج الوصول إلى جلسة Super Admin صالحة في بيئة التطوير الحالية.

## تشغيل المشروع

1. فك ضغط النسخة الجديدة في مجلد مستقل.
2. انسخ ملف `.env` الخاص بك من النسخة السابقة (لا ترسله ولا تضعه في ZIP). **لا تغيّر قاعدة البيانات ولا تنفّذ seed أو SQL مجددًا**.
3. داخل CMD في مجلد المشروع الجديد:

```bat
npm install
npm test
npm start
```

4. سجل دخول المشرف إلى `http://localhost:3000/admin/sign-in` ثم افتح `http://localhost:3000/admin/system-log`.
5. المفروض تظهر سجلات `doctor.license.approved` و`doctor.license.rejected` المخزنة سابقًا، مع رقم المستخدم وسبب العملية. استخدم فلتر "اعتماد / رفض" لعرضها وحدها.
6. زر "تفاصيل" يعرض كل حقول السجل في نافذة. البحث والتاريخ يعملان على الخادم، وتصدير CSV ينزّل السجلات المطابقة حتى 5,000 سجل.

### ماذا لم يتغير؟

- لم نغيّر جدولًا واحدًا أو ننفّذ أي Migration.
- لا توجد أي سجلات تجريبية داخل صفحة سجل النظام بعد الآن.
- تسجيل المريض والطبيب والاعتماد والرفض السابق بقي كما هو.
- لم نربط بقية صفحات المشرف؛ فقط سجل النظام صار يقرأ قاعدة البيانات.
- جلسة Super Admin الحالية للتطوير فقط وليست جاهزة للإنتاج (ما زلنا بحاجة إلى MFA وجلسات أكثر أمانًا).

### استعلام مقارنة اختياري

```sql
SELECT "Log_ID", "Action_Type", "Target_Type", "Target_Reference", "Reason", "User_ID"
FROM sdc."AUDIT_LOG"
ORDER BY "Occurred_At" DESC, "Log_ID" DESC
LIMIT 25;
```

> إن ظهر خطأ "Page rendering error" أو "تعذر"، راجع رسائل CMD؛ لا تحذف قاعدة البيانات. اختبار الكود هنا محلي ولم يشمل اتصال PostgreSQL على جهازك أو اختبار متصفح.
