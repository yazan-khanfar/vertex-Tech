# Smart Dental Clinic — إدارة أطباء العيادة v15

الأساس: `Smart-Dental-Clinic-Clinic-Account-Merged-v14.zip`.

## التغييرات

- ربط زر «إضافة طبيب» الموجود في `/clinic/doctors` بحسابات الأطباء المعتمدين **الفعلية** من PostgreSQL، مع الإبقاء على نفس النافذة والتصميم.
- إنشاء دعوة الانضمام في جدول `sdc."WORKS_AT"` بحالة `pending`، وإشعار الطبيب، وتسجيل `AUDIT_LOG`.
- ظهور الدعوة داخل `/doctor/profile` الأصلية حتى لو كان الطبيب غير مرتبط بأي عيادة، مع قبـول/رفض الدعوة (لا صفحة جديدة).
- لا تصبح العضوية `active` إلا بعد موافقة الطبيب. صلاحيات العيادة قبل تاريخ بدء العمل لا تُمنح، ويبقى الحجز مقيدًا بالتاريخ والدوام.
- متابعة الدعوات المعلقة، إلغاء الدعوة، تعليق العضوية وإعادة تفعيلها من `/clinic/doctors`. يمنع التعليق إن كانت هناك مواعيد قائمة أو جارية. لا يمكن للمدير تعليق عضويته من هنا.
- حماية النماذج برمز CSRF وفحص المدير والطبيب في Backend، والاستعلامات بمعاملات SQL محددة، وإشعارات وسجل تدقيق.
- لا توجد صفحات جديدة، ولا ملفات CSS معدلة، ولا بيانات أطباء وهمية في نموذج الربط.

## التركيب (مهم: هناك ملف SQL مطلوب مرة واحدة)

1. أوقف المشروع وخذ نسخة احتياطية من مجلده وقاعدة `smart_dental_clinic`.
2. افتح pgAdmin → `smart_dental_clinic` → Query Tool.
3. شغّل **فقط** ملف `db/migrations/004_doctor_clinic_invitations.sql` الموجود في الحزمة. يوسّع قيم الحالة المسموحة في `WORKS_AT` لتشمل `pending`. لا يحذف سجلات ولا ينشئ جدولًا.
4. **النسخة الكاملة:** فك الضغط ثم انسخ `.env` المحلي بجوار `package.json` كما هو. **الـPatch:** فك ضغطه وانسخ الملفات داخله فوق مشروع v14 بنفس المسارات، مع الاستبدال. لا تنسخ المجلد الخارجي نفسه.
5. داخل مجلد `package.json`: `npm install` (إذا كانت المكتبات غير مثبتة)، ثم `npm test` ثم `npm start`.
6. لا تشغّل SQL إنشاء القاعدة الأصلية، ولا أوامر Seed، ولا تحذف أي حساب.

## اختبار من المتصفح

1. ادخل بحساب مدير عيادة معتمدة، ثم `/clinic/doctors` → «إضافة طبيب» → اختر طبيبًا معتمدًا مسجّلًا ليس عضوًا في هذه العيادة. سيملأ النموذج بيانات الطبيب المهنية للعرض فقط. حدّد تاريخ بدء العمل، واضغط «إرسال دعوة الانضمام».
2. يجب ظهور الطبيب في قائمة «بانتظار الطبيب»، وعدم ظهور عضويته كعضوية فعالة حتى يوافق.
3. افتح حساب الطبيب على `/doctor/profile`، واقبل الدعوة في قسم «دعوات الانضمام للعيادات».
4. ارجع لصفحة أطباء العيادة وتحقق من ظهوره في بطاقات الأطباء. ضبط الدوام من صفحة تفاصيل الطبيب الموجودة، وإسناد الخدمات من صفحة `/clinic/services` الموجودة.
5. جرّب رفض دعوة أخرى، ثم إلغاء دعوة ثالثة من العيادة. يجب منع إعادة استخدام دعوة ألغيَت/رُفضت من النموذج القديم.
6. جرّب تعليق عضوية الطبيب بدون مواعيد قائمة ثم إعادة تفعيلها. جرّب التعليق لطبيب له موعد مؤكد، والمفروض يرفض حتى لا تتأثر الحجوزات.
7. سجّل الدخول كطبيب آخر وتأكد أنه لا يستطيع اتخاذ قرار بدل الطبيب المدعو. تحقق من سجل التدقيق والإشعارات.

## حدود التحقق

نجحت اختبارات Node المستقلة، وفحص عرض الـ110 صفحة، وفحص المسارات والأجزاء المشتركة. **لم يتم إجراء اختبار مباشر على PostgreSQL الموجود في جهازك** أو تجربة متصفح فعلية في بيئة بناء الملف. تعذر تثبيت مكتبات `npm` هنا بسبب عدم توفر حزمها في الكاش المحلي؛ لذا سيبقى تشغيل `npm test` و`npm start` على جهازك خطوة تحقق ضرورية.

**لا تعتبر دور العيادة كاملًا بعد هذا التحديث.** ما زالت صفحات أخرى تحت المراجعة صفحةً صفحةً وفق تقرير التدقيق v11.
